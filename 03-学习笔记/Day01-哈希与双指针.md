## 一、今日模板回顾

### 哈希表
```python
# 模板速记：值 → 索引映射
seen = {}
for i, num in enumerate(nums):
    if target - num in seen:
        return [seen[target - num], i]
    seen[num] = i
```

### 双指针（对撞）
```python
left, right = 0, len(nums) - 1
while left < right:
    if nums[left] + nums[right] == target:
        return [left, right]
    elif nums[left] + nums[right] < target:
        left += 1
    else:
        right -= 1
```

### 双指针（快慢）
```python
slow = fast = 0
while fast < len(nums):
    if nums[fast] != 0:
        nums[slow], nums[fast] = nums[fast], nums[slow]
        slow += 1
    fast += 1
```

## 二、做题记录

### 1. 两数之和（Easy）
- **核心思路：** 哈希表存「值 → 下标」，边扫边查 `target - nums[i]` 是否已在表里（**先查再插**，天然避开同元素自配）。
- **代码实现：** `lc-plugin-template/cpp-template/leetcode/editor/cn/two-sum.cpp`
- **复杂度：** O(n) / O(n)
- **掌握程度：** ✅（10-06 二刷勾）
- **感悟/易错点：**
  + 小改进：`mp.count(x)` 之后再 `mp[x]` 会做两次哈希查找，用 `auto it = mp.find(x)` 一次拿到迭代器即可。

### 2. 字母异位词分组（Medium）
- **核心思路：** 给每个串做规范化编码（26 字母计数 → `"#c0#c1#..."` 字符串）当哈希 key，同 key 的串归一组；最后把 map 的 value 收集进结果。
- **代码实现：** `group-anagrams.cpp`
- **复杂度：** O(n·L)（计数编码）或 O(n·L·logL)（排序编码）/ O(n·L)
- **掌握程度：** 🔄（10-06 二刷后仍不熟，**待三刷**）
- **感悟/易错点：**
+ encoding 实现 
  - 计数法比排序法快，且 `#` 分隔符能消除歧义（避免 "1,11" 与 "11,1" 拼出同一串），写法没问题。
+ 何时引用
  - range-for 里 `auto c` 是**逐元素拷贝**：`strs` 拷 string、`mp` 拷 pair<string, vector> 都不便宜 → 只读写 `const auto&`，要改写 `auto&`，纯小值类型（int）才用 `auto`。
  - 同理 `encoding(string& s)` 收不到临时串，参数应写 `const string&`。
+ 哈希表怎么用, 怎么遍历
  - 遍历：`for (const auto& [k, v] : mp)`（C++17 结构化绑定）或 `it->first / it->second`。
  - 「查存在再取值」用一次 `find`，别 `count` + `[]` 查两遍；`mp[c_enc].push_back(c)` 一句可以顶替整个 if/else——key 不存在时会自动默认构造空 vector。
+ unordered_map和map怎么选
  - 默认 `unordered_map`（均摊 O(1)）；只有需要**按键有序、遍历顺序稳定**或最坏 O(log n) 保证时才用 `map`。警惕 unordered 的均摊不是真 O(1)（见题 3）。

### 3. 最长连续序列（Medium）
- **核心思路：** 起点法——只从「`x-1` 不存在」的 x 往后走链计数；每条链只被自己的起点走一遍，总工作量 O(n)。
- **代码实现：** `longest-consecutive-sequence.cpp`（10-06 已从遍历 `nums` 修正为遍历 `mp` 键）
- **复杂度：** 平均 O(n) / O(n)
- **掌握程度：** 🔄（**待三刷**）
- **感悟/易错点：**
+ 从set里面开始遍历
  - 对，这就是超时真凶：外层**必须遍历去重后的键集合**（set / map 的 key），遍历原数组时重复的「链起点值」会把同一条链重走 k 次，最坏退化成 O(n²)（`[1,1,...,1,2,3,...,n/2]`）。跟哈希碰撞攻击无关。
  - 等价写法：遍历时 `erase` 已用元素；防劣化兜底可换排序法或自定义 hash。

### 4. 移动零（Easy）
- **核心思路：** 快慢指针：fast 探非零元素写到 slow 位置，扫完后 slow 之后统一补 0（覆盖式，比交换写次数更少）。
- **代码实现：** `move-zeroes.cpp`
- **复杂度：** O(n) / O(1)
- **掌握程度：** ✅（10-06 二刷勾）
- **感悟/易错点：**
+ `++a`：先把 a+1，再返回新值；`a++`：先返回 a 原来的值，再把 a+1。
  - 补充：单独成句时两者效果相同，作表达式用时取值不同；对迭代器统一用前缀 `++it`（`a++` 要先拷贝旧值，对重类型多一次开销）。

### 5. 盛最多水的容器（Medium）
- **核心思路：** 对撞指针，每次记录面积后**移动较矮的一侧**——移动较高侧宽度必减 1 而高度受短板压制，不可能变大。
- **代码实现：** `container-with-most-water.cpp`
- **复杂度：** O(n) / O(1)
- **掌握程度：** ✅（10-06 二刷勾）
- **感悟/易错点：**
+ ok
  - 两侧等高时任移一侧都对，你的三目 `height[left] > height[right] ? right-- : left++` 正确。

### 6. 三数之和（Medium）
- **核心思路：** 排序 + 固定一个数、内部双指针找两数之和；NSum 通用化：n==2 走对撞，n>2 枚举并递归。
- **代码实现：** `3-sum.cpp`
- **复杂度：** O(n²) / O(log n)（排序栈开销，结果除外）
- **掌握程度：** 🔄（**待三刷**）
- **感悟/易错点：**
+ nums.size()有没有开销? 每次循环都会遍历吗
  - 没有遍历开销：C++11 起标准保证 `size()` 是 O(1)（容器内部记着元素数）。你已经缓存成 `sz`，这个习惯留着无害。
+ 去重?
  - 生成时去重（不是事后清理）：**同层分支一个值只试一次**——`sum == target` 收下解后跳同值、外层递归完 `nums[i]` 后跳同值，重复解根本不会进 res。
  - `sum > / < target` 分支里的跳同值只是移动指针的优化，跳一步也对（同值不影响 sum 的判向）。
  - 三数之和里数组的重复元素不能预先 `unique` 删掉：`[0,0,0]`、`[-1,-1,2]` 需要用到同值的 2~3 份；想缩小输入只能「每值截断到 ≤3 份」。

### 7. 接雨水（Hard）
- **核心思路：** 每列积水量 = `min(左侧最高, 右侧最高) - 自身高度`；预处理前缀最大值 `left[]` 与后缀最大值 `right[]` 后逐列累加。
- **代码实现：** `trapping-rain-water.cpp`
- **复杂度：** O(n) / O(n)
- **掌握程度：** ✅（10-06 二刷勾；三刷 Day1 时顺带补 O(1) 空间的对撞指针版）
- **感悟/易错点：**
  + 边界 bug：`sz == 0` 时 `right[sz-1]` 越界（LeetCode 约束 n≥1 不会炸，本地 main 测空数组会）。开头加 `if (height.empty()) return 0;`。

## 三、今日总结

**学到的新模板/技巧：**
- 起点法必须遍历去重后的键集合（49 的编码 key、128 的链起点）
- NSum 框架：n==2 对撞、n>2 枚举+递归，去重全部放在生成侧

**遇到的困难：**
- 128 首刷 TLE 的真实原因是重复链起点放大，不是哈希被攻击——归因错过一次，记牢

**遗留问题（需复习）：**
-双指针是不是都用while会好一点?
  - 已答（10-05 看板 / Day02）：**循环条件是「指针关系/收缩判定」用 while**（对撞、滑窗收缩），**步数已知的线性遍历用 for**（快慢扫描）。别一律 while，for 把"走几步"写在头上更易读。
- 三刷队列：49 字母异位词分组 / 128 最长连续序列 / 15 三数之和
