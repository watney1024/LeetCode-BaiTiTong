## 二、做题记录

### 1. 轮转数组（Medium）
- **核心思路：** 向右轮转 k 位 = 把后 k 个元素搬到前面且各自保序 → 三次翻转：整体翻（后 k 个到前面，但顺序反了）→ 翻前 k 个 → 翻后 n-k 个；k 先对 n 取模。
- **代码实现：** `lc-plugin-template/cpp-template/leetcode/editor/cn/rotate-array.cpp`（10-07 首刷，**看了提示**）
- **复杂度：** O(n) / O(1)
- **掌握程度：** 待自评（D+1 = 10-08 当场勾）
- **感悟/易错点：**
  + 自己的 `reverse` 收的是**闭区间** `[start, end]`，所以三段是 `(0, n-1) / (0, k-1) / (k, n-1)`——`k` 和 `k-1` 的口径一错就整体错位，这是本题唯一容易写歪的地方。
  + `swap(nums[left++], nums[right--])`：后缀 `++/--` 在这里正是「先取值后推进」的正解，两行并一行。`left`、`right` 是两个不同对象，不存在同表达式内改读冲突，写法安全。库函数版是 `std::reverse`，手写只为练对撞边界。
  + `k = k % nums.size()`：`size()` 返回无符号 `size_t`，`int k` 会被提升后再取模。k 非负时结果正确，但带符号转换警告；写成 `int n = (int)nums.size(); k %= n;` 更干净，也顺带挡住 n=0 时的除零（线上约束 n≥1 不炸，本地 main 测空会炸）。

### 2. 除自身以外数组的乘积（Medium）
- **核心思路：** `res[i]` = 左侧全体之积 × 右侧全体之积。两遍扫描合成一个数组：左→右用滚动变量把前缀积乘进 `res`，右→左用滚动变量把后缀积乘进 `res`。不用除法，所以 0 天然正确。
- **代码实现：** `product-of-array-except-self.cpp`（10-07 首刷，独立完成）
- **复杂度：** O(n) / O(1)（返回值不计额外空间）
- **掌握程度：** 待自评（D+1 = 10-08 当场勾）
- **感悟/易错点：**
  + `vector<int> res(n, 1)` 的初值 1 是**乘法单位元**——写成 0 整题归零；这个初值正是「两遍累乘能落在同一个数组上」的前提（对比 560 前缀和的 0）。
  + 两遍都是**先记录、后累乘**：`res[i] *= forward_prefix;` 再 `forward_prefix *= nums[i];`。反一步就把自身乘进去了。起点同理——`forward_prefix = nums[0]` 配 `i` 从 1 起，`back_prefix = nums[n-1]` 配 `i` 从 n-2 起，两个端点各自跳过自己。
  + 和 560 对照着记：都是「扫到 i 时维护一个只到 i-1 为止的量」，但 238 的量唯一（前缀积）→ 滚动变量即可；560 要「以任意 j 结尾」的历史全部值 → 必须哈希查表。
  + `int` 溢出是题目送的保证（约束答案在 32 位内），不是写法本身安全；n=10^5 无此约束必炸。
  + 二刷: 前缀积和后缀积只需要使用两个变量维护

### 3. 缺失的第一个正数（Hard）
- **核心思路：** 把数组本身当哈希表——值 v ∈ [1, n] 就该待在下标 `v-1`。一遍把每个元素交换归位，二遍扫第一个 `nums[i] != i+1` 的位置即答案；全对则返回 `n+1`。
- **代码实现：** `first-missing-positive.cpp`（10-07 首刷，**看了提示**）
- **复杂度：** O(n) / O(1)
- **掌握程度：** 待自评（D+1 = 10-08 当场勾）
- **感悟/易错点：**
  + 外层 `for` + 内层 `while`（不是纯 while）：换进来一个新值就原地继续归位，直到「不该归位」或「已在正确位置」才前进。每个元素最多被放对一次，所以交换总次数 ≤ n，整体仍是 O(n)。
  + 归位判据必须是 `nums[nums[i] - 1] != nums[i]`，**不能**写 `nums[i] != i + 1`：后者遇到重复值（`[1,1]`）会把同一个值在自己位置上无限自交换 → 死循环。写目标下标前先由 `nums[i] > 0 && nums[i] < n` 保证 `nums[i]-1` 不越界。
  + 上界写 `< n`（不含 n）也成立：值 n 不需要主动搬，它会随别的交换顺路到位，或在末遍扫描处露出破绽；`<= n` 更贴合直觉，两者都不影响正确性。
  + 判据只能待在 `while` 条件里：`swap` 之后 `nums[i]` 已经变了，判据必须重算，不能提到外面缓存。

  + 二刷: swap的时候要swap数组, 不能swap(nums[k - 1], nums[i]);

### 4. 矩阵置零（Medium）
- **核心思路：** 不开额外的 `bool` 数组，把**首行和首列本身当标记位**。四步：① 两个 bool 先记下首行、首列原本是否含 0（它们自己的命运）；② 遍历内部 `i≥1, j≥1`，遇到 0 就把信息投影到 `matrix[i][0]` 和 `matrix[0][j]`；③ 按标记分别把内部行、内部列置零；④ 最后按 bool 处理首行、首列。
- **代码实现：** `lc-plugin-template/cpp-template/leetcode/editor/cn/set-matrix-zeroes.cpp`（10-08 首刷；首版有两处下标 bug + 一处编译错误，走查时发现，见下）
- **复杂度：** O(m·n) / O(1)
- **掌握程度：** 待自评（D+1 = 10-09 当场勾；下标起点是自己没验证过的点，按**整题默**验收）
- **感悟/易错点：**
+ index从几开始很重要
  - 今天在这句话上摔了两次，三处下标各是一个坑：
    1. **标记循环必须 `i≥1, j≥1`**。`matrix[0][0]` 同时充当「第 0 行标记」和「第 0 列标记」，`j` 从 0 起时，`matrix[i][0]==0` 会顺手把 `matrix[0][0]` 写成 0，等于**误报第 0 行含 0**。反例 `[[1,2],[0,3]]` → 得 `[[0,0],[0,0]]`，应为 `[[0,2],[0,0]]`。
    2. **按行置零的循环必须从 `i=1`**。`matrix[0][0]` 本身是 0 时，若 `i=0` 也走这个分支，就把存放在第 0 行的**列标记** `matrix[0][j]` 抹成 0，紧接着的列循环读到假标记就多清掉若干列。反例 `[[0,1],[2,3]]` → 得 `[[0,0],[0,0]]`，应为 `[[0,0],[0,3]]`。
    3. 兜底块 `if (row_zero)` 的循环变量是 `i`、写入却用了 `matrix[0][j]` → `j` 不在作用域，**编译不过**。收尾这两段是「整行/整列」操作，别和标记数组的读写混用同名变量。
  - 记法：**首行首列 = 标记位，两个 bool = 首行首列自己的命运**。凡是读标记、写标记的循环都不能碰 0 行 0 列，碰了就必须先问「这个格子是不是兼任两种标记」。
  - 列循环保留 `j=0` 其实**无害**，因为 `matrix[0][0]` 全程没被写过；但这是侥幸成立，统一从 1 起更好读。
  - 另有 `O(m+n)` 空间的两个 bool/vector 版：逻辑不会绕，代价是空间。面试时先说清「能不能改输入」再选版本。

### 5. 螺旋矩阵（Medium）
- **核心思路：** 四条边界 `top/bottom/left/right` 逐圈收缩，每圈固定四段「右 → 下 → 左 → 上」，**每段走完立刻收缩它自己那条边**，收缩后的新边界给下一段用。
- **代码实现：** `spiral-matrix.cpp`（10-08 首刷，独立完成；对拍 3 万组随机 m×n 矩阵 0 错）
- **复杂度：** O(m·n) / O(1)（不计输出数组）
- **掌握程度：** 待自评（D+1 = 10-09 当场勾）
- **感悟/易错点：**
+ 需检查 top <= bottom, left <= right
  - 四个段里**只有第 3、4 段需要额外 `if`**，原因值得记：第 1、2 段的循环条件是 `i <= right` / `i <= bottom`，边界交叉时条件自然为假、循环体一次都不进；而第 3、4 段是反向走，终止条件写成 `i >= left` / `i >= top`，**挡不住「边界已经交叉」**——单行剩余时 `top > bottom` 但 `right >= left` 仍成立，会把同一行再倒着走一遍（多出 n 个重复元素）。
  - 顺序不能调：第 4 段 `for (i = bottom; i >= top; --i)` 用的已经是第 3 段末尾 `--bottom` 之后的值。先收缩再走、还是先走再收缩，写错就漏角或重角。
  - 矩阵是 m×n 而非方阵，`bottom = m - 1`、`right = n - 1` 要分开取；`n = matrix[0].size()` 写在 `m == 0` 判定**之前**，空矩阵是 UB（线上 m,n≥1 不炸，本地 main 测空会炸）——和 189 的 `k % nums.size()`、42 的 `right[sz-1]` 同一族毛病。
  - 变体 59（螺旋矩阵 II）是同一套边界收缩，只是把 `push_back` 换成按序填值。

### 6. 旋转图像（Medium）
- **核心思路：** 顺时针 90° = **主对角线转置 + 每行左右翻转**（思路一，两个标准动作）；思路二 = 把旋转看成位置的置换，**四元素环状交换**，一圈一次到位。
- **代码实现：** `rotate-image.cpp`（思路一，10-08 首刷；首版翻转段边界错，走查时发现）；思路二见 [[02-Wiki/题目详解/48-旋转图像]]
- **复杂度：** O(n²) / O(1)，两版同
- **掌握程度：** 待自评（D+1 = 10-09 当场勾；翻转段边界是自己没验证过的点，按**整题默**验收）→ **二刷 10-12（P0-R2 整题默）：思路一 ✅ 一次写成 ／ 思路二 🟡 未写，半项未验收**。转置（`j = i + 1` 起）+ 行内首尾交换（`j < n / 2`）一遍过，**首刷那个 `j <= n/2` 只在偶数边长出错的卡点已清**（n=1..6 含偶数全部与期望一致）。**但「整题默」的验收项含两个独立考点**：思路二（四元素环交换的四句赋值 + 说出 `n/2`、`(n+1)/2` 两个上界为什么不对称）今天一个字没写，所以本题**不据「一遍过」出列**，下家待裁决（并入 10-13 的 D+1 位，还是回 P0-R3 · 10-25）。另 `int n = matrix[0].size()` 仍写在空判之前——同族第 5 次点名。
- **感悟/易错点：**
+ 边界情况
  - 翻转段写成 `for (j = 0; j <= n / 2; ++j)` 会多做一次 `swap(matrix[i][n/2], matrix[i][n-1-n/2])`：
    - **n 为奇数**：`j == n/2` 正是中心列，自己和自己换 → 无副作用，**侥幸正确**（力扣样例 n=3 就是这一类，样例给不出这个信号）。
    - **n 为偶数**：`n-1-n/2 == n/2-1`，把上一轮刚换好的那一对**又换回去**，行的一半被还原 → `n=4` 时期望 `13 9 5 1|14 10 6 2|...`，错版出 `13 5 9 1|14 6 10 2|...`。
    - 结论：上界应是 `j < n / 2`；自测必须专门造**偶数边长**，光跑样例过得了的题不代表对。
  - 思路二的下标链必须**倒着推**：顺映射是 `(i,j) → (j, n-1-i)`，但赋值要写「新 (i,j) 的值来自哪」，即逆映射 `(a,b) ← (n-1-b, a)`，于是链是 `(i,j) ← (n-1-j,i) ← (n-1-i,n-1-j) ← (j,n-1-i) ← 旧 (i,j)`，`temp` 存链尾那个即将被覆盖的起点。顺着写就把还没取走的值覆盖掉了。
  - 思路二遍历范围 `i < n/2`、`j < (n+1)/2`：每环只处理一个代表（左上四分之一），环数 = ⌊n/2⌋×⌈n/2⌉ = n²/4。两个上界**不对称是给奇数边长准备的**——n=5 时中心列 `j=2` 自成 `(0,2)←(2,0)←(4,2)←(2,4)`，上界写成 `n/2` 就漏掉这一环（实测 5 万组错 21428 组，全在奇数 n）。
  - 和 189 同族：都是原地重排，189 用三次翻转、48 用转置+翻转。但**转置法只对方阵成立**（矩形数组转置会换形状），48 的 n×n 约束是它的前提。

### 7. 搜索二维矩阵 II（Medium）
- **核心思路：** 从**右上角**出发的阶梯搜索：`matrix[row][col] > target` → 该列全部偏大，`col--`；`< target` → 该行全部偏小，`row++`。每步稳定排除一整行或一整列，至多 m+n 步。
- **代码实现：** `search-a-2-d-matrix-ii.cpp`（10-08 首刷，独立完成；对拍 2 万组行列严格递增矩阵 0 错）
- **复杂度：** O(m+n) / O(1)
- **掌握程度：** 待自评（D+1 = 10-09 当场勾）
- **感悟/易错点：**
+ 从右上角开始搜
  - 选起点的真正判据是**「两个方向的单调性相反」**：右上角满足「往左更小、往下更大」，所以一次比较能砍掉一整行或一整列。左下角同理（`row = m-1, col = 0`，大 → 上，小 → 右）。**左上角和右下角不行**——那两个角往右、往下（或往左、往上）的单调性相同，比较结果无法排除任何一条完整的线。
  - 循环条件 `row < m && col >= 0` 把越界判定交给循环头，比在循环体里做边界检查干净；`col -= 1` 与 `row += 1` 各带一句注释「排除当前列 / 排除当前行」，这就是本题的不变式。
  - 对比 [[02-Wiki/题目详解/74-搜索二维矩阵|74 搜索二维矩阵]]：74 是**全局有序**（每行首元素大于上一行末元素），可以展平成一维二分 O(log mn)；240 只有**行列各自有序**，展平后不有序，所以只能阶梯走 O(m+n)（另有逐行二分 O(m log n)、分治两版）。数据规模 m,n ≤ 1000 时 O(m+n) 完全够。

### 3b 总结（2026-10-08 · 73 / 54 / 48 / 240）

**学到的新模板/技巧：**
- **首行首列当标记数组（O(1) 空间的预处理技巧）**：把「哪行哪列要清零」的信息压进矩阵自己的边界，两个 bool 单独保存边界原本的命运——73 是这套技巧的标准题，同族还有 289（生命游戏，用 2/3 状态编码原地改）、75（颜色分类，用指针当标记）。
- **四边界收缩（螺旋遍历）**：`top/bottom/left/right` 每段走完即收缩，反向段必须额外判 `top <= bottom` / `left <= right`。
- **旋转 = 转置 + 翻转**（方阵专属），以及它的置换视角：**四元素环状交换**——顺时针 90° 的顺映射 `(i,j)→(j,n-1-i)`，赋值要按逆映射倒推，遍历只取每环的一个代表（左上 1/4，`n/2 × (n+1)/2`）。
- **单调性相反的角当起点（阶梯搜索）**：240 从右上角出发，每步排除一整行或一整列，O(m+n)；判据是「两个方向单调性相反」，左上/右下角不满足。

**遇到的困难：**
